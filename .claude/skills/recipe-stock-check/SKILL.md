# レシピ在庫チェック

レシピの材料と手持ちの在庫を突き合わせ、買い物リストを作る。

## 手順

### 1. レシピの材料を読み取る

- 画像が添付されていればそれを読む
- `05-recipe-stock-check/レシピ画像/` のファイルを指定された場合はそれを読む
- テキストで材料を渡された場合はそのまま使う

材料名と分量を書き出す。**調味料を飛ばさないこと**（醤油・酒・みりん・ごま油なども材料）。

### 2. 在庫を読む

Google Drive コネクタの `read_file_content` ツールで、スプレッドシート「食材在庫」を読む。

```
fileId: 1p_UQwARsowSZlru0RYNXkYHgYNnDmHfJDTBbtPsK1ww
```

（ツール名は接続ごとに接頭辞が付く。`read_file_content` を含むものを使う）

- **「状態」列が「在庫」の行だけ**を対象にする。`消費済` `破棄` `取消` は手元にないので無視する
- 使う列は 登録日 / 食材名 / 期限 / ラベル / 状態（「ラベル」は賞味期限か消費期限）

### 3. 突き合わせる

意味で照合する。表記ゆれ・言い換え・ブランド名を解決すること。

| レシピの表記 | 在庫の表記 | 判定 |
|---|---|---|
| 薄力粉 | クッキングフラワー | 同一 |
| 卵 | たまご | 同一 |
| 鶏がらスープの素 | 鶏がらスープ | 同一 |
| ヨーグルト | 明治ブルガリアヨーグルト | 同一 |

**似ているだけの別物を一致させないこと。** 牛乳と豆乳、片栗粉と小麦粉、酒と酢はそれぞれ別物。

判断に迷う場合は一致させず「買うもの」に入れ、その旨を添える。

### 4. 出力する

以下の3区分。順番は固定。該当0件の区分は見出しごと省略する。

```
【レシピ名】

■ 在庫あり（N件）
・鶏がらスープ    登録 9/6・期限 2028-06-05
・醤油            登録 8/1・期限 2027-03-31

⚠ 在庫ありだが要確認（N件）
・片栗粉          登録 9/6・期限 2026-06-09（89日超過）

■ 買うもの（N件）
・豚ひき肉（150g）
・長ねぎ（1本）
```

**規則:**

- **登録日を必ず併記する。** 古い登録ほど残りが少ない可能性があり、買うかどうかの判断材料になる
- **期限切れは「要確認」に入れる。** 勝手に「買うもの」へ移さない（実物を見れば使えることがある）
- 期限が近い（7日以内）ものも「要確認」に入れ、残日数を添える
- 「買うもの」にはレシピ上の分量を括弧で添える
- 最後に一行、分量までは判定していない旨を添える

## 制約（必ず守る）

在庫シートは **1行＝1個** で数量を持っていない。「牛乳200ml必要」に対して足りるかどうかは**判定できない**。

- 「あるか・ないか」までしか答えない
- 推測で「足りる」「足りない」と言わない
- 登録日を示して、判断は本人に委ねる

## 在庫に調味料が見当たらない場合

常備調味料はLINE Botで在庫登録する運用になっている。レシピの調味料が軒並み在庫にない場合は、
未登録の可能性が高い。買い物リストに並べる前にその可能性を伝え、登録用の文面を提案する。

```
醤油は2027年3月31日、ごま油は2027年6月30日、みりんは2027年8月31日
```

この形式でLINE Botに送れば一括登録できる。

## 関連

- 在庫の登録・消費・週次通知は `04-food-expiry` のLINE Botが担当（Google Apps Script上で稼働）
- このスキルは**読み取りのみ**。スプレッドシートへの書き込みはできない
