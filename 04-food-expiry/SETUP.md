# MVP① セットアップ手順

LINE に食材の写真を送ると、賞味期限を読み取って返信する Bot。
所要時間：30〜40分。

---

## 1. LINE Developers で Bot を作る（15分）

1. https://developers.line.biz/console/ に LINE アカウントでログイン
2. **プロバイダーを作成**（名前は任意。例：`personal`）
3. そのプロバイダー内で **新規チャネル作成 → Messaging API** を選択
   - チャネル名：例「賞味期限メモ」
   - 大業種／小業種：任意
   - ※ 個人利用でも無料枠内で使えます
4. 作成後、**Messaging API 設定**タブを開く
   - 一番下の「**チャネルアクセストークン（長期）**」→ **発行** をクリック
   - 表示された文字列をコピー → これが `LINE_CHANNEL_ACCESS_TOKEN`
   - 同じ画面の「**応答メッセージ**」を **オフ**、「**あいさつメッセージ**」は任意
     （オンのままだと定型文が二重に返ってきます）
   - 「Webhookの利用」は **オン**（URL は手順3で設定）
5. 同じ画面の QR コードから、**自分の LINE で友だち追加**しておく

---

## 2. Anthropic API キーを取る（5分）

1. https://console.anthropic.com/ でアカウント作成
2. **Billing** でクレジットを購入（最低 $5 から。個人利用なら当面これで足ります）
3. **API keys → Create Key** → 表示されたキー（`sk-ant-...`）をコピー
   → これが `ANTHROPIC_API_KEY`

**費用の目安**：`Code.gs` 冒頭でタスクごとにモデルを分けています。

| 用途 | 定数 | 既定 | 目安 |
|---|---|---|---|
| 写真の読み取り | `MODEL_VISION` | `claude-sonnet-5` | 約1.1円/枚 |
| テキスト解析・在庫照合 | `MODEL_TEXT` | `claude-haiku-4-5` | 約0.4円/回 |

「牛乳使った」のような定型の言い回しは正規表現で処理するため、APIを呼びません。

1日に写真1枚＋操作数回で、月100円程度です。読み取りを外すようなら
`MODEL_VISION` を `claude-opus-5`（約2.7円/枚）に上げてください。

実際の使用量は https://console.anthropic.com/settings/usage で確認できます。

---

## 3. GAS にデプロイする（10分）

1. https://script.google.com/ → **新しいプロジェクト**
2. プロジェクト名を「食材賞味期限」などに変更
3. 左の `コード.gs` を全消しして、本フォルダの **`Code.gs` の中身を貼り付け**
4. 左メニュー **プロジェクトの設定** → 「`appsscript.json` マニフェスト ファイルを
   エディタで表示する」に **チェック** → エディタに現れた `appsscript.json` を
   本フォルダの内容で置き換え
5. 同じ **プロジェクトの設定** ページ下部 → **スクリプト プロパティ** に追加：

   | プロパティ | 値 |
   |---|---|
   | `LINE_CHANNEL_ACCESS_TOKEN` | 手順1でコピーしたトークン |
   | `ANTHROPIC_API_KEY` | 手順2でコピーしたキー |

6. エディタで関数 `testConfig` を選んで **実行**
   - 初回は権限承認のダイアログ（「このアプリは確認されていません」→ 詳細 → 移動）
   - 実行ログに `Claude API 疎通: HTTP 200` が出れば OK
7. 右上 **デプロイ → 新しいデプロイ**
   - 種類：**ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**（LINE のサーバーから叩くため必須）
   - デプロイ → 表示された **ウェブアプリの URL** をコピー

---

## 4. LINE と GAS をつなぐ（3分）

1. LINE Developers の **Messaging API 設定** → **Webhook URL** に
   手順3でコピーした GAS の URL を貼り付け → **更新**
2. 「**検証**」ボタンを押す → 成功すれば接続完了
   （失敗する場合はデプロイのアクセス設定が「全員」になっているか確認）

---

## 5. 使ってみる

友だち追加した Bot に、賞味期限が写った写真を送るだけ。

返信例：
```
商品: 明治おいしい牛乳
消費期限: 2026-09-12
→ あと 6日
印字: 26.09.12
```

読み取りが怪しいときは確度と理由も返します：
```
賞味期限: 2026-11-30（月末まで）
→ あと 85日
印字: 2026.11
※ 読み取り確度: medium（日付の印字がかすれており月までしか判別できません）
　違っていたら撮り直してください。
```

**自分専用にしたい場合**：Bot に `id` と送るとあなたの userId が返るので、
それをスクリプトプロパティ `ALLOWED_USER_ID` に設定してください。
他人が Bot を友だち追加しても API 費用が発生しなくなります。

---

## 既知の制約（MVP のため未対応）

- **署名検証ができない**：GAS の `doPost` は HTTP ヘッダーを取れないため、
  LINE の `X-Line-Signature` を検証できません。URL が漏れなければ実害は小さいですが、
  `ALLOWED_USER_ID` の設定を推奨します。
- **記録しない**：現状は読み取って返すだけ。スプレッドシートへの保存と
  期限接近の通知は次のステップ（MVP②）です。
- **画像は 4MB まで**：それを超えるとエラーメッセージを返します。
- **修正フローがない**：読み取り結果が違っても訂正できません。②で追加します。

# MVP② 記録と週次通知のセットアップ

コードを最新版に差し替えたあと、**エディタから2つの関数を1回ずつ実行**します。

## 1. 記録先のスプレッドシートを作る

1. GASエディタで関数プルダウンから **`setupSpreadsheet`** を選び、**実行**
2. 初回は権限承認（スプレッドシートへのアクセス）が出るので許可
3. 実行ログに出た URL がシートです。開いてブックマークしておくと便利

この関数は「食材在庫」という名前のスプレッドシートを新規作成し、そのIDをスクリプトプロパティ `SPREADSHEET_ID` に自動保存します。**2回目以降に実行しても作り直しません**（設定済みならURLを表示するだけ）。

## 2. 通知先を設定する（未設定の場合）

Botに `id` と送って返ってきた userId を、スクリプトプロパティ **`ALLOWED_USER_ID`** に設定してください。週次通知の送信先を兼ねています。未設定だと通知が送れません。

## 3. 土曜朝のトリガーを設定する

1. 関数プルダウンから **`setupWeeklyTrigger`** を選び、**実行**
2. 実行ログに「毎週土曜 8時台に notifyWeekly を実行するトリガーを設定しました」と出れば完了

左サイドバーの **⏰ トリガー** で確認できます。時刻は「8時〜9時の間」というGASの仕様上の幅があります。

> この関数は、同名 `notifyWeekly` の古いトリガーがあれば削除してから作り直します。他の関数のトリガーには触れません。

## 4. 通知の動作確認

土曜まで待たずに確認できます。関数プルダウンから **`notifyWeekly`** を選んで実行してください。該当する食材があればLINEに届きます。

該当がなければ push を送らず、ログに「通知対象なし」と出ます（LINEの無料通数を無駄に使わないため）。

---

## シートの構成

| 列 | 内容 |
|---|---|
| 登録日 / 登録時刻 | 登録したタイミング（日付と時刻で列を分けている） |
| 食材名 / 期限 / 精度 / ラベル / 確度 | 読み取り結果 |
| 入力元 | 写真 or テキスト |
| 原文 | 写真の印字、または発話の該当部分 |
| 状態 | 在庫 / 消費済 / 破棄 / 取消 |
| 更新日時 | 状態を最後に変えた日時 |
| 通知1M / 通知1W | それぞれの通知を送った日 |

**行は削除されません。** 消費も取消も「状態」列の書き換えだけで表現するので、履歴が残ります。誤りは直接シートを編集して直せます。

## 通知のルール

- **毎週土曜の朝**、以下の3区分でまとめて1通だけ届きます
- **残り1か月**：残り30日を切った最初の土曜に1回だけ
- **残り1週間**：残り7日を切った最初の土曜に1回だけ
- **期限切れ**：消費または破棄を報告するまで、毎週先頭に再掲

同じ食材が毎週出続けるのは期限切れのものだけです。

## 使い方（LINE）

| 送る内容 | 動作 |
|---|---|
| 期限が写った写真 | 読み取って登録 |
| `豆乳は2027年2月21日 ヨーグルトは9月17日` | 解析して登録 |
| `牛乳は消費期限が9月10日` | **消費期限**として登録 |
| `牛乳使った` `ヨーグルト食べた` | 消費済みに（複数該当時は番号で選択） |
| `豆腐捨てた` | 破棄として記録 |
| `1` `2` … | 候補を尋ねられたときの回答 |
| `やめる` | 選択を中止 |
| `買い物リストに牛乳と卵を追加` | 買い物リストに追加 |
| `牛乳買った` | 買い物リストから外す |
| `買い物リスト` | 買い物リストの一覧 |
| `買い物リストを全部削除` | 買い物リストを空にする |
| `在庫` | 在庫の一覧 |
| `取消` | 直前の操作を取り消す |
| `ヘルプ` | 使い方 |
| `id` | userId を表示 |

## 買い物リスト

在庫とは別の「買い物リスト」シートで管理します。シートは初回利用時に自動で用意されます。

| 列 | 内容 |
|---|---|
| 追加日 | リストに入れた日 |
| 品名 | 買うもの |
| 状態 | 未購入 / 購入済 / 取消 |
| 更新日時 | 状態を最後に変えた日時 |

```
買い物リストに牛乳と卵と長ねぎを追加
  ↓
買い物リストに追加しました（3件）

1. 牛乳
2. 卵
3. 長ねぎ
```

- **すでにリストにあるものは追加されません**（`※ すでにリストにあります: 牛乳`）
- `牛乳買った` でリストから外れます。**在庫への登録は別**で、期限を添えて送ってください
- `買い物リストを全部削除` は、行を消さず「購入済」にします。`取消` で戻せます
- これらの操作は**ほとんどAPIを使いません**（費用がかかりません）

**在庫と買い物リストは別物です。** 言い方で区別しています。

| 言い方 | 動作 |
|---|---|
| 牛乳**使った** | 在庫を消費 |
| 牛乳**買った** | 買い物リストから外す |
| 牛乳は9月10日 | 在庫に登録 |

## 賞味期限と消費期限の区別

どちらか明示して伝えると、その種別で登録され、返信・一覧・通知すべてに表示される。

```
牛乳は消費期限が9月10日、味噌は賞味期限9月30日
```

```
2件を登録しました

1. 牛乳
  消費期限 2026-09-10（4日）

2. 味噌
  賞味期限 2026-09-30（24日）
```

- **「消費期限」と明示したときだけ消費期限**になる。それ以外はすべて賞味期限として登録される
- 複数の食材をまとめて伝えた場合、種別は食材ごとに判定される
  （`牛乳は消費期限9月10日、味噌は9月30日` → 牛乳だけが消費期限）
- 写真から登録する場合は、パッケージに「消費期限」と印字されているものだけが消費期限になる
- シートの「ラベル」列を直接編集すれば後から変更できる

消費期限は「過ぎたら食べない方がよい」という意味を持つため、賞味期限と取り違えないよう表示を分けている。

## 重複登録の確認

同じ**食材名と期限**の在庫がすでにある状態で登録すると、追加せずに確認します。

```
同じものが既に在庫にあります。

・明治ブルガリアヨーグルト（2026-09-17）

2つ目を買ったのなら「1」、二重登録なら「2」を送ってください。
1. 登録する
2. 登録しない
```

- **個数を明示した場合は確認しません。** 「牛乳を2個 9月11日」と送れば、そのまま2件登録されます
- 1回の写真に同じ商品が2つ写っている場合も確認しません（実物が2つあるため）
- 新規と重複が混在する場合、**新規は先に登録**し、重複分だけ確認します
- 個数は最大20までに丸められます（誤認識による大量登録の防止）

## まとめて消費・破棄する

個数や「全部」を伝えれば、まとめて処理できます。

```
片栗粉2つ捨てた
牛乳全部使った
```

## 複数該当したときの選択

**迷う余地があるときだけ**尋ねます。次の場合は質問せずそのまま処理します。

| 状況 | 動作 |
|---|---|
| 候補が1件 | そのまま記録 |
| 候補が伝えた個数以下（例：「2つ捨てた」で在庫2件） | 全部そのまま記録 |
| 候補が**名前も期限も同じ**（どれを選んでも同じ） | 先頭から必要数だけ記録 |

期限が違うものが並ぶ場合だけ、こう尋ねます。

```
「牛乳」に該当する在庫が 3件あります。
消費した 2件を、番号をカンマ区切りで答えてください。（例: 1,3）

1. 牛乳（賞味期限 2026-09-09・あと3日）
2. 牛乳（賞味期限 2026-09-15・あと9日）
3. 牛乳（賞味期限 2026-09-26・あと20日）

（すべてなら「全部」、やめる場合は「やめる」）
```

回答は `1` `1,3` `1 3` `1と3` `2番` `全部` のいずれでも通ります。

- 「豆腐と牛乳使った」のように複数伝えた場合、**一意に決まるものは先に記録**し、曖昧なものだけ順に尋ねます
- 質問は**10分で失効**します（古い質問に後から番号だけ返して誤操作するのを防ぐため）
- 番号以外を送ると選択は打ち切られ、その入力が通常のコマンドとして処理されます

# MVP③ リッチメニューのセットアップ

トーク下部に常設のメニューを出します。押すと入力欄に「期限登録 」などが
差し込まれるので、続きを打って送るだけで種別が確定します。
言い回しからの推定をしなくなるため、「牛乳買った（買い物リスト）」と
「牛乳使った（在庫の消費）」の取り違えが起きません。

```
┌────────┬────────┬────────┬────────┐
│ 期限登録 │ 使用済  │ 破棄済  │  取消   │
├────────┼────────┼────────┼────────┤
│ 買い物  │ 買い物  │ 買い物  │ 買い物  │
│ リスト  │ リスト  │ リスト  │ リスト  │
│  追加   │  削除   │  表示   │ 全削除  │
└────────┴────────┴────────┴────────┘
```

上段の3つと下段の左2つは、押すと入力欄に接頭辞が入るだけです。
**「取消」「表示」「全削除」は押すとすぐ実行されます。**

全削除は行を消さず「購入済」にするだけなので、押し間違えても
「取消」で元に戻せます。

## 1. 画像のファイルを追加する

GASエディタ左の **ファイル → ＋ → スクリプト** で `RichMenuImage` という名前の
ファイルを作り、本フォルダの **`RichMenuImage.gs` の中身を貼り付け**ます。

リッチメニューの画像（2500×1686 PNG）を base64 で持たせたものです。Drive を
使わずに済ませるためコードに埋め込んでいます。中身を手で編集しないでください。

## 2. 実行する

関数プルダウンから **`setupRichMenu`** を選び、**実行**します。

実行ログにこう出れば完了です。

```
作成: richmenu-xxxxxxxx
画像をアップロード: 40KB
既定のリッチメニューに設定しました。トークを開き直すと出ます。
```

スマホの LINE でトークを開き直すと、下部にメニューが出ます。
出ないときはアプリを再起動してください。

> この関数は**古いリッチメニューを削除してから作り直します**。画像や配置を
> 変えたら、そのつど実行し直してください。何度実行しても増えません。

## 3. やめたいとき

関数 **`deleteRichMenus`** を実行するとメニューが消えます。
接頭辞の手入力（`期限登録 牛乳 9月10日`）は、メニューがなくても使えます。

## 画像を作り直す

`richmenu.py` が `richmenu.png` と `RichMenuImage.gs` を生成します。

```
python richmenu.py richmenu.png
```

配置を変える場合は、`Code.gs` の `RICHMENU_COLS` / `RICHMENU_ROWS` /
`RICHMENU_CELLS` を画像の格子と一致させてください。ずれていると
`testConfig` が「画像サイズと不一致」と警告します。

## 接頭辞の一覧

メニューを使わず手で打つこともできます。**区切りの空白が必要**です。

| 接頭辞 | 動作 | 別の言い方 |
|---|---|---|
| `期限登録 牛乳 9月10日` | 在庫に登録 | `登録` |
| `使用済 牛乳` | 在庫を消費 | `使った` `消費` |
| `破棄済 豆腐` | 破棄として記録 | `捨てた` `破棄` |
| `買い物リスト追加 牛乳と卵` | 買い物リストに追加 | `買い物追加` |
| `買い物リスト削除 牛乳` | 買い物リストから外す | `買った` `購入` |

接頭辞なしの従来どおりの言い方（`牛乳使った` `豆乳は2027年2月21日`）も
そのまま使えます。その場合は言い回しから種別を推定します。

## Quick Reply との関係

候補が複数あるときの番号選択と、重複登録の確認では、これまでどおり
入力欄の上にボタン（Quick Reply）が出ます。こちらは**スマホのみ**で、
PC版のLINEでは表示されません。リッチメニューは PC版でも表示されます。

# 付録 clasp で反映を自動化する

ここまでの手順では、`Code.gs` を直したら GAS エディタに手で貼り直していた。
`clasp`（Apps Script の公式CLI）を入れると、**ローカルから `push` するだけ**になる。
2,200行のファイルをコピペしなくてよくなり、貼り忘れ・部分貼り付けもなくなる。

Claude Code に作業させている場合、`clasp push` まで実行させられるようになる。

## 何が変わるか

| | いままで | clasp 導入後 |
|---|---|---|
| コードの反映 | 全選択→GASエディタに貼り付け→保存 | `clasp push` |
| 本番への反映 | デプロイ→デプロイを管理→編集→新バージョン→デプロイ | `clasp deploy -i <ID>` |
| ファイルの追加 | エディタで手作業（`RichMenuImage` など） | `push` に含まれる |
| 原本 | リポジトリ（ただし GAS 側と乖離しうる） | リポジトリ（構造的に一本化） |

## 1. clasp を入れる（初回のみ）

```bash
npm install -g @google/clasp@3
clasp --version   # 3.4.1 など
```

## 2. Apps Script API を有効にする（初回のみ）

https://script.google.com/home/usersettings を開き、
**「Google Apps Script API」を オン** にする。これを忘れると `push` が 403 で落ちる。

## 3. ログインする（初回のみ）

```bash
clasp login
```

ブラウザが開いて Google の認証画面が出る。許可すると `~/.clasprc.json` に
トークンが保存され、以後は聞かれない。

> ブラウザが開けない環境（SSH 先など）では `clasp login --no-localhost` を使う。

## 4. プロジェクトを紐づける（初回のみ）

スクリプトIDは GAS エディタの **プロジェクトの設定 → スクリプト ID** で確認できる。
URL（`https://script.google.com/home/projects/<ここ>/edit`）からも読める。

```bash
cd 04-food-expiry
clasp clone <スクリプトID> --rootDir .
```

`.clasp.json` が作られる。**このファイルは `.gitignore` で除外済み**（スクリプトIDが
入るため）。`clone` は GAS 側のファイルを落としてくるので、ローカルの `Code.gs` が
上書きされていないか `git diff` で必ず確認すること。GAS 側が古ければ
`git checkout 04-food-expiry/Code.gs` で戻してから `push` する。

## 5. デプロイIDを控える（初回のみ）

Webアプリの URL を変えずに更新するには、既存デプロイのIDが要る。

```bash
clasp list-deployments
```

`@1`, `@2`... と並ぶうち、**LINE の Webhook URL に対応するもの**の
`AKfycb...` がそれ。GAS エディタの「デプロイを管理」でも確認できる。

## 6. 日常の操作

```bash
cd 04-food-expiry

clasp push                              # コードを GAS に反映（保存まで）
clasp deploy -i <デプロイID> -d "説明"   # 新バージョンとして本番に反映
```

**`push` だけでは LINE に反映されない。** GAS のウェブアプリは、デプロイし直すまで
古いバージョンが動き続ける。「直したのに直っていない」の原因はほぼこれ。

| コマンド | 用途 |
|---|---|
| `clasp status` | 次の `push` で送られるファイルの確認 |
| `clasp push` | コードを反映 |
| `clasp push -w` | ファイル変更を監視して自動 push（開発中に便利） |
| `clasp pull` | GAS 側で直接編集してしまったものを回収 |
| `clasp deploy -i <ID> -d "..."` | 既存デプロイを新バージョンに更新 |
| `clasp list-deployments` | デプロイの一覧とID |
| `clasp open-script` | GAS エディタをブラウザで開く |
| `clasp logs` | 実行ログの取得（下記の制約あり） |

## 送られるファイルの範囲

`.claspignore` で **`Code.gs` / `RichMenuImage.gs` / `appsscript.json` の3つだけ**に
限定してある。これがないと clasp は `icons/*.html` も HTML ファイルとして
GAS プロジェクトに送り込んでしまう。ファイルを増やしたら `.claspignore` にも追記すること。

## できないこと・注意

- **`clasp logs` はそのままでは使えないことがある。** Cloud Logging の参照には
  標準GCPプロジェクトへの切り替えが必要。ログは GAS エディタの「実行数」画面で足りる。
- **`clasp run`（関数の直接実行）は準備が重い。** 標準GCPプロジェクトへの切り替え、
  `appsscript.json` への `oauthScopes` 明示、実行用APIデプロイが要る。
  このBotは `doPost` のウェブアプリなので、動作確認は LINE から実際に送るのが早い。
- **`push` は GAS 側の編集を上書きする。** GAS エディタで直接直したくなったら、
  先に `clasp pull` で回収してからにする。
- **`~/.clasprc.json` は秘密情報。** Google アカウントへのアクセストークンなので、
  リポジトリにもクラウドにも置かない。ルートの `.gitignore` で除外済み。
- トークンの期限が切れたら `clasp login` をやり直す。年に数回程度。

## GitHub Actions で自動デプロイしない理由

`~/.clasprc.json` を Secrets に入れれば push 契機の自動デプロイもできるが、
個人利用では見合わないと判断している。

- リフレッシュトークンは Google アカウント全体に効き、スコープも広い
- main への push が即本番反映になり、デプロイ前の一拍（安全弁）がなくなる
- clasp の CLI 仕様変更で workflow が黙って壊れる保守コストが乗る

修正の頻度が上がって手動デプロイが律速になったら、そのとき入れればよい。
